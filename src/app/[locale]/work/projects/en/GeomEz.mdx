## Overview

GeomEz was born out of a real need. While studying Kotlin and working on a personal engineering project, I realized I needed tools to work with computational geometry in a practical way. At the same time, I was discovering the features that set Kotlin apart from Java and noticed how much the language's syntax could simplify the development of applications involving geometric concepts. I decided to combine both goals and build a library that made the most of what Kotlin has to offer.

The result is a clean, expressive and type-safe API for representing and manipulating geometric primitives, performing affine transformations, working with parametric curves and surfaces and, optionally, visualizing everything via matplotlib.

## Architecture

The project is split into two independent modules:

- **geomez-core**: a pure geometry module with no rendering dependencies. It can be added to any JVM project with no additional overhead.
- **geomez-visualization**: an optional module that adds `.plot()` and `.addPlotCommands()` functions to all core types, delegating rendering to Python via the [matplotlib4k](https://github.com/daanrsantiago/matplotlib4k) bridge.

## Geometric Primitives

The library provides a rich set of abstractions for 2D and 3D geometry.

**In 2D:**
- `Point2D`, `Vector2D`, `Direction2D` — fundamental elements with floating-point delta-safe equality
- `CoordinateSystem2D` — coordinate systems represented by 3x3 affine matrices
- `Polynomial`, `LinearSpline`, `CubicSpline` — scalar functions with analytical differentiation and integration
- `BezierCurve`, `CubicBezierSpline2D`, `ParametricCurve2D` — flexible parametric curves
- `Polygon2D`, `ConvexPolygon2D` — polygons with area computation via the shoelace formula

**In 3D:**
- `Point3D`, `Vector3D`, `Direction3D` — three-dimensional counterparts of the 2D primitives
- `CoordinateSystem3D` — 4x4 affine matrices for spatial transformations
- `ParametricCurve3D`, `ParametricSurface3D` — parametric curves and surfaces with numerical normals
- `Curve3D` — a discrete, ordered collection of 3D points

## The Power of Abstractions

Despite appearing simple, the library's abstractions are extremely powerful. The fluid and elegant API can represent complex geometries with just a few lines of code.

A real-world example is the modeling of a 2D airfoil. The aerodynamic profile is accurately described using Bezier curves and cubic splines that capture both the pressure and suction sides of the wing:

![Airfoil modeled with GeomEz](/images/projects/GeomEz/plot_airfoil.png)

In three dimensions, the same parametric approach allows modeling far more complex geometries. A complete propeller blade, for example, is defined as a 3D parametric surface that combines the airfoil profile with rotations and scaling along the radial direction:

![Propeller modeled with GeomEz](/images/projects/GeomEz/plot_propeller.png)

## Kotlin in Practice

The Kotlin features that set the language apart from Java were essential for building an expressive and concise API. Three of them deserve special attention.

### Operator Overloading

In Java, adding two points would require something like `point1.add(point2)` or `Point2D.sum(point1, point2)`. In Kotlin, with operator overloading, the operation becomes completely natural and readable:

### Destructuring Declarations

Destructuring allows you to extract components from objects directly, making the code far more readable than accessing properties one by one:

<CodeBlock className="my-24"
    compact
    lineNumbers
    codeInstances={[
        {
            code: `// Direct coordinate extraction
val (x, y)    = Point2D(5.0, 7.0)
val (x, y, z) = Point3D(1.0, 2.0, 3.0)

// Used internally to build the affine matrix of a coordinate system
val (x1, x2) = xDirection
val (y1, y2) = yDirection
val (p1, p2) = origin

val affineMatrix = SimpleMatrix(arrayOf(
    doubleArrayOf(x1, y1, p1),
    doubleArrayOf(x2, y2, p2),
    doubleArrayOf(0.0, 0.0, 1.0)
))`,
            label: 'Destructuring',
            language: 'kotlin'
        },
    ]}
    copyButton
/>

Without destructuring, every access would require `xDirection.x`, `xDirection.y`, `origin.x` and so on, making the code more verbose and less expressive.

### Extension Functions

Extension functions allow adding behavior to existing classes without modifying them or creating subclasses. In GeomEz, they are used extensively to add operators to EJML matrices and to enrich lists of points with geometric operations:

## Technologies

- **Kotlin 2.x** — primary language, leveraging operator overloading, destructuring and extension functions
- **EJML (Efficient Java Matrix Library)** — 3x3 and 4x4 affine matrix operations
- **matplotlib4k** — Kotlin-Python bridge for delegating rendering to matplotlib
- **MkDocs** — documentation hosted at [geomez.com](https://geomez.com)
